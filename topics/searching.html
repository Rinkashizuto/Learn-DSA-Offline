Searching Algorithms

Sequential Linear Search versus Divide-and-Conquer Binary Search.

1. What is Searching?

Searching is the fundamental problem of locating the position of a specific target value inside a collection. In computer science, there are two primary ways to search through an array:

💡 Real-Life Analogy: Looking Up a Word in a 1,000-Page Dictionary

Imagine you want to look up the word "Penguin" in a thick printed dictionary.

Linear Search: You open page 1 ("Aardvark"), then page 2, page 3... and read every page sequentially until page 650. This takes up to 1,000 tedious steps (O(n)).

Binary Search: Because the dictionary is alphabetically sorted, you open the book right at page 500. You see "Monkey". Since "P" comes after "M", you instantly throw away the entire first 500 pages! You open the middle of the remaining half (page 750), see "Rhino", and throw away pages 750–1000. In just 10 quick flips, you find the exact word! That is O(log n).

4. C++17 Implementation

📄 search_algorithms.cpp 
#include <iostream>
#include <vector>

// 1. Linear Search: O(n)
int linearSearch(const std::vector<int>& arr, int target) {
    for (size_t i = 0; i < arr.size(); ++i) {
        if (arr[i] == target) {
            return static_cast<int>(i);
        }
    }
    return -1;
}

// 2. Binary Search: O(log n) - requires sorted array!
int binarySearch(const std::vector<int>& arr, int target) {
    int low = 0;
    int high = static_cast<int>(arr.size()) - 1;

    while (low <= high) {
        // Prevent integer overflow: low + (high - low) / 2
        int mid = low + (high - low) / 2;

        if (arr[mid] == target) {
            return mid; // Found!
        } else if (target < arr[mid]) {
            high = mid - 1; // Discard right half
        } else {
            low = mid + 1;  // Discard left half
        }
    }
    return -1; // Not found
}

5. Common Mistakes & When To Use

⚠️ Common Beginner Mistakes
  • Binary Search on Unsorted Data: Binary Search assumes monotonic order. Running it on unsorted data produces completely wrong, unpredictable answers!
  • Integer Overflow Bug: Writing mid = (low + high) / 2. If low + high exceeds the 32-bit signed integer limit ($2^{31}-1$), it overflows to a negative number. Always write low + (high - low) / 2!
  • Loop Condition Off-by-One: Using while (low < high) instead of while (low <= high) misses the target if it sits at the final single element.
✅ When Should You Use Which?
  • Linear Search: Use when data is unsorted and you only perform a single one-off search (sorting first would take $O(n \log n)$, slower than a single $O(n)$ scan).
  • Binary Search: Use whenever data is already sorted, or whenever you can formulate the problem as a monotonic answer function (Binary Search on Answer).
