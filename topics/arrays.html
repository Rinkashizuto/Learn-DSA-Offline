Arrays

Contiguous memory, lightning-fast index access, and the trade-offs of shifting.

1. What is an Array?

An array is the most fundamental data structure in computer science. It is a collection of items stored in contiguous (unbroken, side-by-side) slots in your computer's RAM memory. Because every item has the exact same size and slots sit right next to each other, the computer can jump to any slot instantly using an index (starting at 0).

💡 Real-Life Analogy: Numbered School Lockers

Imagine a hallway with a continuous row of numbered school lockers numbered [0] through [7]. If someone says "Open locker number 4", you don't need to walk from locker 0, 1, 2, and 3 first. You can walk straight to locker 4 with zero wasted time! That is why array lookups are instant O(1).

However, imagine every locker already has a backpack in it. If a new student joins and needs locker [2], what happens? Every student from locker 2 onward has to pack up and physically shift one locker to the right! That is why inserting or deleting into the middle of an array requires O(n) shifting work.

3. Time & Space Complexity

Operation Best Case Average Case Worst Case Space Complexity
Random Access (Read arr[i]) O(1) O(1) O(1) O(1)
Search (by value) O(1) (if 1st item) O(n) O(n) (if absent) O(1)
Insertion (at index i) O(1) (at end) O(n) O(n) (at index 0) O(1) auxiliary
Deletion (at index i) O(1) (at end) O(n) O(n) (at index 0) O(1) auxiliary
🤔 What does Big-O mean here?

O(1) (Constant Time): Takes the exact same fraction of a microsecond whether your array contains 5 items or 5 billion items. Array access is mathematical: Address = BaseAddress + index * itemSize.

O(n) (Linear Time): If your array has n items, you may have to inspect or shift all n items one by one. If you double the size of the array, the worst-case time doubles.

4. C++17 Implementation

Standard, clean C++ code for linear search, insertion, and deletion. Watch the code lines highlight as you step through animations in the visualizer above!

📄 array_operations.cpp 
#include <iostream>
#include <vector>

// 1. Linear Search: returns index or -1 if absent
int linearSearch(const std::vector<int>& arr, int target) {
    for (size_t i = 0; i < arr.size(); ++i) {
        if (arr[i] == target) {
            return static_cast<int>(i); // Found match!
        }
    }
    return -1; // Target not found
}

// 2. Insert at index: shifts elements to right
void insertAt(std::vector<int>& arr, int val, size_t index) {
    if (index > arr.size()) return;
    arr.push_back(0); // Allocate extra space at end
    for (size_t j = arr.size() - 1; j > index; --j) {
        arr[j] = arr[j - 1]; // Shift rightwards
    }
    arr[index] = val; // Place new element
}

// 3. Delete at index: shifts elements to left
void deleteAt(std::vector<int>& arr, size_t index) {
    if (index >= arr.size()) return;
    for (size_t j = index; j + 1 < arr.size(); ++j) {
        arr[j] = arr[j + 1]; // Shift leftwards
    }
    arr.pop_back(); // Remove vacated last slot
}

5. Common Mistakes & When To Use

⚠️ Common Beginner Mistakes
  • Off-by-One Errors: Forgetting that arrays are zero-indexed. An array of size 5 has indices 0, 1, 2, 3, 4. Accessing arr[5] is undefined behavior!
  • Out-of-Bounds Memory Corruption: In raw C++, accessing invalid indices can read garbage memory or crash your program with a segmentation fault.
  • Assuming Search is O(1): Knowing an item's index is O(1), but finding where a value is located requires scanning the whole array O(n).
✅ When Should You Use Arrays?
  • Known Size or Fast Random Access: When you need to read elements in random order using an index in $O(1)$ time.
  • Cache Locality: Modern CPUs love contiguous memory! Arrays load whole cache lines at once, making them significantly faster than linked pointer structures.
  • Appending at the End: Adding or removing elements at the very end of a dynamic array (`std::vector::push_back`) is amortized $O(1)$.
