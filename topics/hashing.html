Hashing & Hash Tables

Lightning-fast key-value lookups with collision resolution algorithms.

1. What is Hashing?

A Hash Table (or Hash Map) is an associative data structure that maps keys to values with an astonishing average time complexity of O(1) for search, insertion, and deletion. It works by running the key through a hash function that calculates a numerical index inside an array.

💡 Real-Life Analogy: Coat Check at a Theater

When you enter a winter theater, you hand the attendant your heavy coat (your data). They hand you a ticket with a number printed on it: #42 (your hash index). Your coat is hung immediately on hook 42.

When you return after the show, you don't inspect all 500 coats one by one. You simply say: "Here is ticket #42!" The attendant walks straight to hook 42 in O(1) instant time. But what if two different people are accidentally assigned ticket 42? That is called a collision, and we must have a strategy to handle it!

1. Separate Chaining

Every bucket in the array holds the head of a linked list. If multiple keys hash to the same bucket, they simply hang off each other as linked list nodes.

2. Open Addressing (Linear Probing)

All elements stay in the primary array. If bucket h is occupied, we check (h + 1) % size, (h + 2) % size, and so on until the next empty slot is found.

3. Time & Space Complexity

Operation Average Case Worst Case (All Collisions) Space Complexity
Search (by key) O(1) O(n) O(1)
Insert (key, value) O(1) O(n) O(1)
Delete (by key) O(1) O(n) O(1)
🤔 Why is Worst-Case O(n)?

If a terrible hash function maps every single key to bucket index [0], all $n$ items will end up in the exact same linked list! Searching that bucket degrades into a linear scan $O(n)$. High-quality hash functions distribute keys evenly to guarantee $O(1)$ average time.

4. C++17 Implementation

📄 hash_table.cpp 
#include <iostream>
#include <vector>
#include <list>

class HashTableChaining {
private:
    static const int TABLE_SIZE = 7;
    std::vector<std::list<int>> table;

    // Hash function: O(1)
    int hashFunction(int key) const {
        return std::abs(key) % TABLE_SIZE;
    }

public:
    HashTableChaining() : table(TABLE_SIZE) {}

    // 1. Insert: O(1) avg
    void insert(int key) {
        int bucket = hashFunction(key);
        table[bucket].push_back(key);
    }

    // 2. Search: O(1) avg
    bool search(int key) const {
        int bucket = hashFunction(key);
        for (int val : table[bucket]) {
            if (val == key) return true;
        }
        return false;
    }

    // 3. Delete: O(1) avg
    void remove(int key) {
        int bucket = hashFunction(key);
        table[bucket].remove(key);
    }
};

5. Common Mistakes & When To Use

⚠️ Common Beginner Mistakes
  • Assuming Hash Tables are Sorted: Standard hash maps (`std::unordered_map`) have no sorted order. If you need sorted keys, use a Binary Search Tree / Red-Black Tree (`std::map`).
  • Ignoring the Load Factor ($\alpha$): As elements fill up the table ($\alpha = N / M > 0.75$), collisions spike dramatically. Production hash tables rehash and double their bucket count automatically.
  • Primary Clustering: In linear probing, long contiguous blocks of occupied cells form, increasing search times.
✅ When Should You Use Hashing?
  • Instant Key-Value Lookups: When you need $O(1)$ lookups by name, ID, or unique string.
  • Frequency Counters: Counting occurrences of words or numbers in a dataset.
  • Eliminating Nested Loops: Turning $O(n^2)$ search loops into $O(n)$ single-pass lookups (e.g. the classic Two Sum algorithm).
