Linked Lists

Dynamic chains of heap-allocated nodes connected via pointers.

1. What is a Linked List?

Unlike an array, which requires a single unbroken block of memory, a linked list stores items in separate pieces of memory called Nodes. Each node holds its data and a pointer (memory address) pointing to the next node in line. The chain ends when a node points to nullptr (nowhere).

💡 Real-Life Analogy: A Scavenger Hunt

Think of a scavenger hunt. You are handed Clue #1. It gives you a piece of trivia and tells you: "Your next clue is hidden in the kitchen cupboard." You walk to the kitchen to find Clue #2, which tells you to go to the garage for Clue #3.

You can't jump straight to Clue #5 because you have no idea where it's hidden until you visit Clues 1, 2, 3, and 4! That's why random access is O(n). But adding a new clue into the middle is effortless: you just change the address written on one card to point to the new card—no shifting of lockers required!

Singly Linked List

Each node only stores a pointer to the next node. Traversal is strictly one-way (forward).

Doubly Linked List

Each node stores two pointers: next AND prev. You can traverse forward and backward!

3. Time & Space Complexity

Operation Singly Linked Doubly Linked Space Complexity
Access by Index k O(n) O(n) O(1)
Search (by value) O(n) O(n) O(1)
Insert at Head O(1) O(1) O(1)
Insert at Tail (with tail ptr) O(1) O(1) O(1)
Delete Node (given pointer to it) O(n) (need prev node) O(1) (has prev pointer!) O(1)
🤔 Array vs. Linked List Trade-off

Use an Array when you need fast index access (arr[i]) or want superior CPU cache performance. Use a Linked List when you frequently insert or delete items at the head/tail without wanting the memory reallocation or shifting penalties of arrays.

4. C++17 Implementation

📄 linked_list.cpp 
#include <iostream>

struct Node {
    int data;
    Node* next = nullptr;
    Node* prev = nullptr; // Used in doubly linked lists
    explicit Node(int val) : data(val), next(nullptr), prev(nullptr) {}
};

// 1. Search for value
bool search(Node* head, int target) {
    Node* curr = head;
    while (curr != nullptr) {
        if (curr->data == target) {
            return true;
        }
        curr = curr->next;
    }
    return false;
}

// 2. Insert at Head: O(1)
void insertHead(Node*& head, int val) {
    Node* newNode = new Node(val);
    newNode->next = head;
    if (head != nullptr) {
        head->prev = newNode;
    }
    head = newNode;
}

// 3. Insert at Tail: O(1) if tail pointer maintained
void insertTail(Node*& head, Node*& tail, int val) {
    Node* newNode = new Node(val);
    if (tail == nullptr) {
        head = tail = newNode;
        return;
    }
    tail->next = newNode;
    newNode->prev = tail;
    tail = newNode;
}

// 4. Delete by Value
void deleteNode(Node*& head, int val) {
    if (head == nullptr) return;
    if (head->data == val) {
        Node* temp = head;
        head = head->next;
        if (head) head->prev = nullptr;
        delete temp;
        return;
    }
    Node* curr = head;
    while (curr->next && curr->next->data != val) {
        curr = curr->next;
    }
    if (curr->next != nullptr) {
        Node* target = curr->next;
        curr->next = target->next;
        delete target;
    }
}

5. Common Mistakes & When To Use

⚠️ Common Beginner Mistakes
  • Losing the Head Pointer: If you reassign head = head->next without keeping track, the first node is lost in memory forever (Memory Leak)!
  • Dereferencing nullptr: Checking curr->next->data before verifying whether curr->next == nullptr will crash your program.
  • Forgetting to call delete: In C++, nodes allocated with new must be manually deleted to avoid memory leaks.
✅ When Should You Use Linked Lists?
  • Frequent Insertions at Ends: Need constant $O(1)$ push/pop at the front or back without memory reallocation.
  • Building other DSA: Underpins stacks, queues, hash table separate chaining, and adjacency lists for graphs.
  • Unknown or Dynamic Size: You don't know ahead of time how many items you'll store and memory is fragmented.
