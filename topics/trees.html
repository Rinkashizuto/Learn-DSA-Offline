Trees & BST

Hierarchical structures, tree traversals, and logarithmic O(log n) binary search trees.

1. What is a Tree & Binary Search Tree?

Up to this point, all our data structures were linear (flat rows of memory). A Tree is a non-linear, hierarchical data structure composed of Nodes connected by edges. The topmost node is called the Root, and nodes with no children are called Leaves.

💡 Real-Life Analogy: Company Organizational Chart

Think of a company chart. At the very top sits the CEO (the Root). The CEO manages two Vice Presidents (Left and Right children). Each Vice President manages two Directors, and down the tree it branches until you reach individual team contributors with no direct reports (the Leaves).

A Binary Search Tree (BST) adds one golden rule: for every node, all values in its left subtree are smaller, and all values in its right subtree are larger. At every single node, you eliminate half of the remaining tree—giving you blazing fast O(log n) search speeds!

3. Time & Space Complexity

Operation Average Case (Balanced) Worst Case (Skewed) Space Complexity
Search (BST) O(log n) O(n) O(h) recursion stack
Insert (BST) O(log n) O(n) O(h) recursion stack
Delete (BST) O(log n) O(n) O(h) recursion stack
Tree Traversals (In/Pre/Post) O(n) O(n) O(h) recursion stack
🤔 What does O(log n) mean?

$\log_2(1,000,000) \approx 20$. In a balanced BST containing one million nodes, finding any element takes at most 20 comparisons!

4. C++17 Implementation

📄 bst.cpp 
#include <iostream>
#include <vector>

struct TreeNode {
    int val;
    TreeNode* left = nullptr;
    TreeNode* right = nullptr;
    explicit TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

// 1. Search in BST: O(log n) avg
bool searchBST(TreeNode* root, int target) {
    if (root == nullptr) return false;
    if (root->val == target) return true;
    if (target < root->val) {
        return searchBST(root->left, target);
    } else {
        return searchBST(root->right, target);
    }
}

// 2. Traversals: O(n) visits all nodes
void inorder(TreeNode* root) {
    if (root == nullptr) return;
    inorder(root->left);
    std::cout << root->val << " "; // Left -> Root -> Right (Sorted!)
    inorder(root->right);
}

void preorder(TreeNode* root) {
    if (root == nullptr) return;
    std::cout << root->val << " "; // Root -> Left -> Right
    preorder(root->left);
    preorder(root->right);
}

void postorder(TreeNode* root) {
    if (root == nullptr) return;
    postorder(root->left);
    postorder(root->right);
    std::cout << root->val << " "; // Left -> Right -> Root
}

5. Common Mistakes & When To Use

⚠️ Common Beginner Mistakes
  • The Skewed Tree Trap: If you insert already sorted data (e.g. 1, 2, 3, 4, 5) into a naive BST, each node becomes a right child. The tree turns into a linked list and search degrades from $O(\log n)$ to $O(n)$! (Self-balancing trees like AVL or Red-Black trees fix this).
  • Missing Recursive Base Cases: Always verify if (root == nullptr) return; first, or your recursive functions will crash with stack overflow.
✅ When Should You Use Trees?
  • Ordered Range Queries: Finding all values between 20 and 50 is fast and straightforward in a BST.
  • File Systems & DOM: Directory folders containing subfolders and files naturally form hierarchical trees.
  • Auto-Complete & Dictionaries: Prefix trees (Tries) allow fast prefix-based string searches.
